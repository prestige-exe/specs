# V.42 and V.42bis – Error Correction and Data Compression

by ITU-T (then CCITT) Study Group XVII
V.42 first approved at the IXth CCITT Plenary Assembly, Melbourne,
November 1988, as "Error-correcting procedures for DCEs using
asynchronous-to-synchronous conversion". V.42bis approved in 1989 as
"Data compression procedures for data circuit-terminating equipment
(DCE) using error correction procedures". Both have been revised
several times; the substantive content of LAPM and BTLZ has not
changed.

V.42 and V.42bis are two distinct recommendations that are almost
always implemented together. V.42 specifies the error-correction
layer: how a DCE detects a corrupt or lost frame and retransmits it.
V.42bis specifies a compression layer that rides on top of V.42's
reliable byte stream. A modem that does V.42bis without V.42 is
nonsensical because the compression assumes a guaranteed-delivery
substrate.

## V.42 architecture

V.42 sits between the asynchronous DTE-to-DCE interface (the COM port
on the computer) and the synchronous DCE-to-DCE link (the carrier on
the phone line). It is responsible for:

1. Stripping start and stop bits from the DTE side and inserting them
   on the receive side, presenting an async byte stream to the
   computer while running synchronous framing on the wire.
2. Framing the byte stream into HDLC-style frames with a checksum.
3. Acknowledging good frames, retransmitting bad frames.
4. Flow-controlling the DTE when the link is congested.

V.42 specifies two error-correcting protocols:

- **LAPM** (Link Access Procedure for Modems). The primary protocol,
  derived from the LAPB used in X.25 and from LAPD used in ISDN.
- **Alternative Procedure**. MNP classes 2 through 4, included so a
  V.42 modem can interoperate with the very large installed base of
  MNP-only modems.

Both protocols are negotiated at link setup. The "V.42 detection
phase" is the in-band handshake that decides which (if either) is in
use.

## LAPM frame structure

LAPM frames are HDLC-derived. The on-the-wire format is:

```
+------+---------+---------+----------+--------+------+
| FLAG | ADDRESS | CONTROL |   INFO   |   FCS  | FLAG |
| 0x7E |  1 byte | 1 or 2  | 0..N oct | 2 oct  | 0x7E |
+------+---------+---------+----------+--------+------+
```

- **FLAG**: 0x7E, the standard HDLC frame delimiter. Bit-stuffing
  prevents 0x7E from appearing inside the frame body.
- **ADDRESS**: a single byte. The Command/Response bit and the
  Extended Address bit are defined; in normal operation the value is
  0x03 (response from secondary) or 0x01 (command from primary).
  LAPM is balanced, so both ends can issue commands.
- **CONTROL**: HDLC control field. One octet in modulo-8 mode, two
  octets in modulo-128 mode. Identifies the frame as Information (I),
  Supervisory (S: RR, RNR, REJ, SREJ), or Unnumbered (U: SABME, UA,
  DM, DISC, FRMR, UI, XID).
- **INFO**: variable-length payload. Maximum size is negotiated
  during XID exchange, default 128 octets, up to 1024.
- **FCS**: 16-bit CRC over the address, control, and info fields.
  Polynomial is the CCITT standard 0x1021.

LAPM uses a sliding window. The default window size (k) is 15 in
modulo-128 mode, 7 in modulo-8 mode. Frames are numbered N(S)
(sequence) and N(R) (receive); the receiver ACKs by sending an RR
(Receiver Ready) frame with N(R) set to the next expected sequence
number. REJ requests retransmission from a sequence number; SREJ
(selective reject) requests a specific missing frame.

The LAPM connection is set up with SABME (Set Asynchronous Balanced
Mode Extended), confirmed with UA, and torn down with DISC.

## V.42 detection phase

After carrier is established but before user data flows, the two
modems exchange a detection pattern to determine each other's
capabilities. The originating modem sends ODP (Originator Detection
Pattern):

```
'E' 'C'
```

repeatedly for a defined interval. The answering modem listens; if it
hears ODP it replies with ADP (Answerer Detection Pattern):

```
'A' 'A'
```

When both ends have heard the other's pattern, they proceed to LAPM
setup via SABME. If ODP/ADP is not heard within the timeout (typically
about 750 ms), the modem falls back:

- If the modem supports the MNP alternative procedure, it issues an
  MNP LR (Link Request) frame and attempts an MNP 4 negotiation.
- If that also fails (or is not supported), the link drops to a normal
  (non-error-corrected) connection.

This three-tier fallback is what `AT\N3` (auto-reliable) executes
implicitly.

## XID and parameter negotiation

Once LAPM is established with SABME/UA, the two ends exchange XID
(Exchange Identification) frames. XID carries a list of parameter
groups:

- HDLC Optional Functions (which control-field features are in use).
- Maximum information field length (N401).
- Maximum number of outstanding I-frames (k).
- V.42bis compression parameters (P0, P1, P2, covered below).
- Other vendor-specific items.

Each parameter is encoded as a TLV (type, length, value) inside the
XID info field. Either side may propose; the other side accepts,
modifies, or rejects.

## V.42bis – BTLZ compression

V.42bis specifies British Telecom Lempel-Ziv (BTLZ), an adaptive
dictionary-based compression algorithm. BTLZ is a variant of LZW with
explicit control codes for dictionary maintenance and a "transparent
mode" escape for incompressible data.

### Dictionary

V.42bis builds a string dictionary of variable-length entries. Entries
are added as new strings are encountered. The dictionary is
referenced by an integer codeword.

- **N1** (codeword size): the number of bits per codeword. Negotiated
  between 9 and 12. A 12-bit codeword gives a dictionary of 4096
  entries.
- **N2** (dictionary size): the maximum number of entries. Default is
  2048, range is 512 to 65535. Common deployed values are 2048
  (default) and 4096.
- **N7** (maximum string length): the longest string the dictionary
  will hold. Default 6 characters, range 6 to 250.

The first 256 entries are reserved for the literal byte values 0
through 255. Entries 256, 257, and 258 are reserved for control
codewords:

- 0..255: literal byte.
- 256: ETM (Enter Transparent Mode).
- 257: FLUSH (flush dictionary state).
- 258: STEPUP (increase codeword size by 1 bit).
- 259..: dictionary entries, allocated in order.

### Encoding

The compressor reads input bytes and matches them against the longest
existing dictionary string. When the longest match is found, the
codeword for that string is emitted and a new dictionary entry is
created: the matched string plus the next input byte. The next input
byte then becomes the start of the next match.

When the dictionary fills (codeword count reaches 2^N1 − 1), the
encoder issues a STEPUP control codeword, increasing N1 by one bit
for subsequent codewords. When N1 reaches its negotiated maximum and
the dictionary is full, the oldest unused entries are recycled
(LRU recycling).

### Transparent mode

The escape hatch for already-compressed data. If the compressor
detects that compression is making the byte stream longer (the count
of bits emitted exceeds the count of bits consumed by a configurable
margin), it emits ETM (codeword 256) and switches to "transparent
mode". In transparent mode, bytes are passed through verbatim, no
compression, no dictionary updates. The encoder still inspects the
stream and may switch back to compressed mode when it detects
compressible content.

Transparent mode is what makes V.42bis safe to leave enabled. A
ZModem transfer of a ZIP file under V.42bis sees a brief excursion
into transparent mode and then the link runs at roughly the raw
modulation rate. Compare to MNP 5, which has no equivalent escape and
actually slows down on compressed data.

### Negotiated parameters

The V.42bis parameters carried in XID are:

| Param | Name | Default | Range | Meaning |
| --- | --- | --- | --- | --- |
| P0 | Direction | 3 | 0..3 | Bit 0: compress data from caller. Bit 1: compress data from answerer. |
| P1 | Dictionary size | 2048 | 512..65535 | N2 |
| P2 | String length | 6 | 6..250 | N7 |

P0 = 3 (both directions) is universal. P1 = 2048 is what most modems
negotiate because that is the lowest common denominator; high-end
modems with more RAM negotiate 4096 or higher.

### Compression ratio

On English text, V.42bis achieves roughly 3.5:1 to 4:1 compression.
On already-compressed data (ZIP, JPEG, GIF, MP3) the ratio is 1:1 in
transparent mode. The ITU specification quotes "up to 4:1" as a
marketing-grade figure; in practice on mixed BBS traffic, 2.5:1 to 3:1
is typical.

## Relationship to other layers

```
+--------------------+
| DTE byte stream    |  (the computer's serial port)
+--------------------+
| V.42bis compression| (optional, when both ends negotiate it)
+--------------------+
| LAPM framing       | (V.42 error correction)
+--------------------+
| Modulation         | (V.32bis, V.34, V.90, etc.)
+--------------------+
| Phone line         |
+--------------------+
```

V.42bis is independent of the underlying modulation. The same BTLZ
algorithm runs over a V.32bis 14400 bps link or a V.90 56k link.

## AT command interaction

`AT\N3` selects auto-reliable mode (try LAPM, fall back to MNP 4,
then normal). `AT\N4` requires LAPM. `AT%C2` selects V.42bis
compression; `AT%C3` selects "either V.42bis or MNP 5" with V.42bis
preferred when LAPM is in use.

The result code on a successful V.42 / V.42bis link is typically
`CONNECT 14400/V42BIS` or `CONNECT 14400/LAPM/V42BIS`, the exact text
varying by modem.
